Delegati i lambda izrazi

Delegat je tip koji opisuje potpis metode; varijabla tipa delegata čuva listu metoda koje se pozivaju redom. Zato se metoda može predati drugoj metodi (kao što Task.Run prima posao koji treba izvršiti). Ovdje se vidi što se događa s listom poziva i s rezultatom.

1. Lista poziva (multicast)

Što vidite

Delegat Calc pokazuje na jednu ili više metoda koje primaju int i vraćaju int. Gumbi += dodaju metodu na kraj liste poziva. Gumbi −= uklanjaju zadnju pojavu te metode, a ako je u listi nema, ništa se ne mijenja. Pri pozivu delegata izvršavaju se sve metode u listi, redom, sve s istim x. Iznad liste je naredba u C#-u koja je napravila zadnju promjenu.

Što učiniti
  • Lista počinje s Oduzmi (Calc racun = Oduzmi;). Dodajte Pomnozi i promatrajte koju vrijednost delegat vraća.
  • Dodajte još jednom Oduzmi pa kliknite »−= Oduzmi«: uklanja se zadnja pojava. Zatim »−= Pomnozi« ukloni metodu iz sredine liste. Isprobajte i »−=« za metodu koje nema u listi.
  • Kliknite »racun = null« ili uklonite sve metode: lista je prazna, a delegat null.
  • Upišite x = 100000000: Pomnozi prelije raspon tipa int, kao u C#-u.

delegate int Calc(int x);   const int n = 50;

Problem: pri pozivu se izvrše sve metode u listi, ali delegat vraća samo rezultat zadnje; ostali se tiho odbacuju. Prazan delegat je null i njegov poziv baca NullReferenceException. Kod taskova je to bitno: ako jedan od poslova koje ste predali ne uspije ili njegov rezultat nestane, to često nećete odmah primijetiti.
Rješenje: kad su potrebni svi rezultati, prođite listom ručno (GetInvocationList()), a prazan delegat štitite s ?.Invoke(x).

2. Univerzalna funkcija s uvjetom

Što vidite

Jedna funkcija Ispisi obrađuje niz, a što ispisuje određuje delegat Uvjet koji joj predate. Zeleni elementi zadovoljavaju uvjet, ostali se preskaču.

Što učiniti

Promijenite niz i uvjet. Primijetite da se funkcija nije mijenjala, samo ponašanje koje joj predajete. Isti obrazac koristi Task.Run(posao): biblioteka zna kako izvesti posao, a vi joj kažete koji.

static void Ispisi(int[] niz, Uvjet uvjet)

3. Lambda i closure

Što vidite

Lambda x => x * faktor koristi varijablu faktor koja je izvan nje. Kliknite »Pozovi« pa promijenite klizač i ponovno pozovite.

Što učiniti

Postavite faktor, pozovite, promijenite faktor i pozovite opet. Isti poziv daje drukčiji rezultat jer lambda čita trenutnu vrijednost varijable.

int faktor = ; Calc3 puta = x => x * faktor;

Problem: lambda ne kopira faktor nego čuva referencu na varijablu. Ako je mijenja netko drugi (petlja, druga nit), lambda vidi promjenu. Kod taskova to znači da rezultat ovisi o tome kada se task pokrene, što ne kontrolirate. Pogledajte stranicu »Zamke« (tjedan 2, odjeljak 1) gdje se to događa u petlji.
Rješenje: ako vam treba vrijednost u trenutku stvaranja lambde, spremite je u lokalnu varijablu i nju koristite u lambdi.

4. Koji ugrađeni delegat trebam?

Što vidite

Umjesto vlastitog delegate tipa koristimo ugrađene: Action (ne vraća ništa), Func (vraća vrijednost, zadnji tip u zagradi je povratni) i Predicate (vraća bool). Birate koliko parametara metoda ima i što vraća, a stranica pokazuje odgovarajući tip.

Što učiniti

Postavite 1 parametar i povratni tip bool: dobit ćete Predicate<int>. Postavite 0 parametara i bez povratne vrijednosti: obični Action.

5. Generička klasa Stog<T>

Što vidite

Stog je struktura u kojoj se zadnji stavljeni element prvi skida. ZaSvaki(Action<T>) prolazi elementima od vrha prema dnu i za svaki poziva zadanu akciju. Broji(Predicate<T>) broji elemente koji zadovoljavaju uvjet. Zadaću metode (što raditi s elementom) dajemo kao delegat, pa jedna klasa služi za mnogo namjena.

Što učiniti

Stavite nekoliko brojeva, promijenite uvjet i pozovite Broji. Pozovite ZaSvaki i pratite redoslijed.

Problem: Skini() na praznom stogu ne smije tiho vratiti krivu vrijednost. U vježbi se baca InvalidOperationException. Isprobajte: skidajte dok stog nije prazan.
