Vježba 5: kanceliranje taskova

Paralelno programiranje, tjedan 5. Nakon vježbe znate prekinuti task na zahtjev (CancellationToken), izmjeriti koliko prekid kasni, pisati periodičan posao koji ne kasni sve više i vratiti rezultat prekinutog posla bez dijeljenja podataka.

Priprema

  • Visual Studio 2026 ili JetBrains Rider: otvorite Vjezba5/Vjezba5.sln. Visual Studio Code (uz proširenje C# Dev Kit): File > Open Folder, mapa Vjezba5, konfiguracija »Vježba 5: zadatak N«. Naredbeni redak: u mapi zadatka pokrenite dotnet run (npr. cd Zadatak1_ImeSvakeSekunde pa dotnet run).
  • Projekt cilja .NET 10 (LTS). Ako imate samo Visual Studio 2022, u datoteci .csproj svakog zadatka (i u .vscode/launch.json) promijenite net10.0 u net8.0; zadaci rade jednako.
  • Svaki zadatak je zaseban projekt (mapa ZadatakN_* s datotekom ZadatakN_*.cs) i pokreće se samostalno: u Visual Studiju desni klik na projekt > Set as Startup Project, u Rideru odaberite projekt u popisu konfiguracija.
  • Zadaci mjere vrijeme, pa ih pokrećite u Release konfiguraciji (dotnet run -c Release, u VS Codeu konfiguracija »(Release)«). Zadatak 1 čeka Enter: pokrenite ga u terminalu.
  • Prije vježbe pogledajte prezentaciju za vježbu 5 i kraj predavanja 5 (async/await, blokiranje niti).

Prekid taska: CancellationToken

Task se ne može zaustaviti izvana. Glavna nit samo zatraži prekid, a task ga mora sam provjeriti i završiti.

var izvor = new CancellationTokenSource();
CancellationToken token = izvor.Token;

Task t = Task.Run(() =>
{
    while (!token.IsCancellationRequested)
    {
        // posao
    }
}, token);

Console.ReadLine();
izvor.Cancel();      // postavi zahtjev za prekid
t.Wait();
  • CancellationTokenSource šalje zahtjev (Cancel(), ili CancelAfter(ms) nakon zadanog vremena); CancellationToken se predaje tasku, koji ga provjerava.
  • Token predan metodi Task.Run: ako je prekid zatražen prije nego što task počne, task se ne pokrene.
  • Stanje taska (t.Status) nakon prekida: RanToCompletion ako delegat samo izađe iz petlje, a Canceled ako baci OperationCanceledException. Token predajte i metodi koja stvara task (Task.Run, Task.Factory.StartNew, new Task): bez predanog tokena stanje je u tom slučaju Faulted. Wait() na prekinutom tasku baca AggregateException.

Čekanje koje se može prekinuti. Što poziv napravi kad glavna nit zatraži prekid (token je CancellationToken taska):

pozivkad se zatraži prekidbez prekida
Thread.Sleep(ms)ništa: spava do krajavrati se nakon ms
token.WaitHandle.WaitOne(ms)vrati se odmah, vrati truenakon ms vrati false
token.ThrowIfCancellationRequested()baci OperationCanceledExceptionne radi ništa
await Task.Delay(ms, token)odmah baci TaskCanceledException (vrsta OperationCanceledException)vrati se nakon ms
ograda.SignalAndWait(token)prestane čekati, baci OperationCanceledExceptiončeka ostale

Izmjereno (čekanje 2000 ms, prekid nakon 300 ms): Thread.Sleep 2000 ms, ostali 300–336 ms. Kod koji ne pogleda token prekid ne primijeti.

  1. Upišite svoje ime u konstantu Ime. Pokrenite program pet puta i Enter pritisnite u različitim trenucima. Zapišite izmjerena vremena. Od čega ovise?

Zadatak 3: Periodicno s prekidom Zadatak3_PeriodicnoPrekid.cs

Zadano: test u Main. Test 1 zatraži prekid nakon 3,5 s i mjeri koliko task kasni; test 2 zatraži prekid prije poziva metode. Oba ispisuju stanje taska. Main smijete mijenjati.

Što trebate napraviti:
  1. Napišite metodu static Task Periodicno(Action akcija, int ms, CancellationToken token): poziva akciju svakih ms milisekundi dok se ne zatraži prekid, a vraća task da glavna nit može čekati njegov kraj. Pozivi neka budu u istom rasporedu kao nakon koraka 3 zadatka 2 (k-ti poziv u (k − 1) · ms).
  2. Task mora završiti najkasnije 100 ms nakon Cancel(). Vrijeme mjerite u Releaseu bez debuggera: dotnet run -c Release ili Ctrl+F5 (F5 pokreće program s debuggerom, i u Release konfiguraciji).
  3. U oba testa stanje taska mora biti Canceled, a program ne smije završiti iznimkom.
  4. Što se u testu 2 dogodilo s akcijom? Zašto?

Zadatak 4: Periodicno2<U> Zadatak4_Periodicno2.cs

Zadano: testovi u Main i metoda PeriodicnoUZajednickuListu, koja dodaje vrijednosti u listu dobivenu kao argument, dok je glavna nit tu istu listu čita (test 2).

Što trebate napraviti:
  1. Napišite metodu static Task<List<U>> Periodicno2<U>(Func<U> f, int ms, CancellationToken token): poziva f svakih ms milisekundi, pamti svaku povratnu vrijednost, a nakon prekida lista svih vrijednosti je rezultat taska (Result).
  2. Pokrenite test 1 (prekid nakon 3,5 s, CancelAfter).
  3. Test 2 koristi zadanu metodu. Što se dogodi? Zašto se to ne može dogoditi s vašom metodom Periodicno2?
  4. Popravite test 2 tako da ostane zajednička lista, ali program radi bez greške. Smijete mijenjati test 2 i zadanu metodu PeriodicnoUZajednickuListu.

Predaja
